# AGENTS.md — gmvmax-auto folder conventions

> M10 dashboard + M11 TTAM metrics/presets (shop 1): Tailwind cards, status filter/sort, spinners/cooldown, v51 calendar, TTAM 3-level drills with OMTM scores/verdicts, DB presets + `/presets` manager. Source of truth: `masterplan.md` + `plan.md`. Handoff: `DEV_NOTES.md` (read first — Checkpoint 53 newest, bugs 36–62 + 95–105 + 115–122). User guide: `feature.md`. ## Stack
- Python stdlib server + vanilla JS + Tailwind CDN. `127.0.0.1` only.
- No npm, no build. One server at a time (dashboard owns 8082; use `--port` scratch for smoke).
- `cryptography` (Fernet) approved for this folder only (token encryption, P1). No hand-rolled AES.

## Rules
1. Secrets never in git/chat: `NEON_URL_DEV/PROD`, `GMV_ENC_KEY`, TikTok/Shop keys, Telegram tokens. `git status` must never show them. Verify by key-names + lengths only.
2. Official APIs only. Newest hourly pair is partial by definition (tag it, decide off closed hours) — the old closed-window T-2h rule was dropped per owner 03 Oct for the hourly view; scheduler/auto still never acts on the newest slot.
3. Lock net-vs-gross ROI before first rule (May-2026: ROI includes affiliate/coupons/fees).
4. After EVERY change: `python -m py_compile` + `npx tsc --noEmit` in `online/` + deploy via `deploy_online.py` (build log must list new routes).
5. Never write to `acct_*` from gmv code and vice versa (per-schema roles `acct_app`/`gmv_app` deferred to P1; owner-only for P0).
6. Migrations: schema-qualify EVERY identifier (`acct.x`, `gmv.x`, `core.x` incl. indexes + FK refs); never use reserved words as bare columns (`window`→`win`). Grep-check new SQL before handing to owner.
7. Portal specifics: Neon child branches default to 1-day auto-delete (uncheck for persistent dev); Business API redirect uses `http://localhost:PORT/callback` (IP form rejected); sandbox ad account locked until app approval.
8. Online deploys run from the repo root (`python 2-gmvmax/gmvmax-auto/deploy_online.py`, never `--cwd`); on Windows the script uses `npx.cmd` + shell. New API row fields must be carried through every frontend merge/accumulator (Total view merges LIVE+Product). Credential lookup is per-advertiser — never substitute another shop's token (40001 means wrong token, not no access). Serverless caps: Hobby kills at 60s — batch all per-row write loops (500/chunk); Telegram caps at 4096 chars (rich 32k) — truncate + overflow line. Every report pull gets filtered by the Neon promotion_type map (bugs 16/24). `tsconfig.tsbuildinfo` is gitignored. Rich lessons (bugs 32–34): never put fallible media inside an all-or-nothing blocks send (covers travel solo or not at all); never invent type strings — read the spec anchors first, probe second; verify media URLs by content-type header, never by browser. After every structural edit, re-read the edited region before verifying (edit tool eats neighbors).
10. Sparring mode is ON for this folder (owner order 03 Oct): challenge assumptions, no blind affirmation; feasibility talk gets words only until explicit go.
11. Client/server import wall (bug 36): `"use client"` files import ONLY from `src/lib/ttam-scores.ts` (pure, zero imports) — never from `gmv.ts`/`ttam.ts`/routes (they pull `pg` → browser build dies on dns/net/tls while tsc stays green). Drill dimension rule (bug 37): parent+child ID combos are 40002 at child grains — pull the child grain alone, filter by the get-list ID set client-side.
13. Report pulls loop `total_page` always (B79: page-1-only silently drops rows). DELETE-then-INSERT savers validate uniqueness BEFORE the DELETE and name the culprit in the 400 (B82). Editable-row identity lives in refs with stable keys, never `let` locals or index keys (B80/B81).
14. Dashboard chrome: shared `Shell.tsx` owns top bar + icon sidebar + Settings collapse + toasts (`toast.ts` bus — every save dispatches ok/err). Board tabs are `?shop=&metric=` links at `/gmv-max` with auto-load; empty index at `/`. New pages go top-level with sidebar entries, never nested modals.
12. Security: Vercel Deployment Protection must cover **All Deployments** until the Google app gate is deployed; "Standard Protection" left production public. The Vercel wall also blocks Google callbacks for non-team users, so only the owner may temporarily disable it in a controlled regression-test window; restore immediately on any failed test. Google sign-in accepts only verified, exact emails in `core.access_allowlist` or fixed `AUTH_ADMIN_EMAIL`; `AUTH_ADMIN_EMAIL` alone can manage `/access`. Protected data APIs recheck current membership on every request. With `online/src/app`, middleware must live at `online/src/middleware.ts`; verify the built middleware manifest is populated. Keep webhook/cron public to middleware only because each has its own server-side secret check. `NEXT_PUBLIC_PRESET_WRITE_KEY` is exposed in the browser by definition; never call it secret or rely on it to protect writes. Test signed-out, allowed, denied, and removal-revocation paths before leaving the Vercel wall off.
